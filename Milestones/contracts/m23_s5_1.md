## Objective

Purpose: implement the **pure, in-memory accession candidate and joint entity-accession selection
core** — the accession-level analogue of the existing S4.1 `entity_selector.py` — so that entity and
accession quotas are solved as one joint assignment problem rather than sequentially. Governed
primarily by Decision 013 §5 (selector policy, D10) and the future Decision 018.

**Exact existing accepted objective terms (Decision 013 §5, quoted verbatim — this contract adds
nothing to them):**

> a lexicographic objective (plan §8.4): zero unmet hard quotas, then minimize unresolved/provisional
> evidence, then minimize base-accession count, then stress-accession count, then the ordered vector
> of entity hashes, then the ordered vector of accession hashes;

Decision 013 also already requires: integer/categorical comparisons only (no floating-point
objective), explicit fixed input ordering, deterministic branch ordering, a deterministic
search-node limit, and `infeasible_or_unproven` on exhaustion — never a partial manifest. These
terms are accepted and are not reopened by this contract or by Decision 018.

**Decision 018 must freeze the unresolved accession-specific interpretations before implementation
begins.** The objective terms above are already accepted; what is missing is how several of the
terms and adjacent policies are operationalized for accessions specifically (see "Not frozen by this
contract" below). S5.1 cannot be implemented from Decision 013 §5 alone.

## In scope

**S5.1 is the pure core only.** Exactly two things:

- A pure, in-memory accession-candidate representation and joint entity-accession solver, structured
  like `entity_selector.py` (S4.1): **no SQLite access of any kind**, no network calls, no filing
  text, no outcomes, no clock read.
- Adversarial unit tests for that solver, in-memory only.

Nothing else. In particular, S5.1 does **not** include SQLite access, accession-selection
persistence, `accession_selection_store.py`, frozen-snapshot reconstruction, run-lifecycle writes,
quota-result persistence, or selected-accession persistence — every one of those is S5.2 below.

## Required adversarial test categories (once unblocked)

All are in-memory unit tests over the pure solver. No test under this contract opens SQLite, and
none asserts reserve behavior (S5.4).

- Fail-closed `infeasible_or_unproven` on a genuinely infeasible joint pool, with an empty selection
  (never a partial result).
- Deterministic reproducibility: the same candidate input set produces the same selected entity and
  accession lists across repeated runs and across input orderings.
- Joint-objective interaction: a case where an entity-optimal choice is not accession-optimal, to
  prove the objective is solved jointly rather than sequentially.
- Multi-registrant accession quota satisfied exactly once regardless of registrant-CIK count
  (Decision 013 §4, D9).
- Search-node-limit exhaustion path, including exhaustion after a feasible incumbent was found
  internally.
- Malformed and duplicate accession inputs rejected before any search begins.
- Per-CIK and global accession cap enforcement (plan §4.2 limits).
- Canonical hashing determinism across process runs (once Decision 018 fixes the accession hash
  representation — see "Not frozen by this contract").

`comparison_operator`-aware quota evaluation and composite `(selection_run_id, snapshot_id)`
foreign-key integrity (Decision 016 §6) are **persistence** properties and belong to S5.2's test set,
not this stage's.
