  explicit non-negative ceiling, checks immediately before every transport attempt, permits a

  deterministic clocks, zero sockets, and one rehearsal receipt per rehearsal invocation.
- Produce **one single full-path black-box witness per M3.2A route** (Decision 029 §7). Each route's
  tested `A_reachable` is the transport attempt count observed from **one** `SecClient.fetch()`

  `sec_edgar_calendar_announcement` witness uses the rehearsal-only manifest-resolution fixture of

  `a_reachable_agrees`, and `a_reachable_fully_tested` hold, with `unmeasured_routes` empty and the

  the state its specification names records `completion_status="failed"` with

- `m3.receipt`: `RECEIPT_SCHEMA_VERSION = "m3-execution-receipt/2.0"`, typed receipt construction,

## 9. Exact CLI interface

All artifact arguments are relative paths below a required absolute `--evidence-root`. The root is
resolved and validated before any read or write, and its absolute value is never printed or
serialized. All commands use exit codes `0` success, `1` configuration error, `2` usage, `3` stage
not enabled, and `4` gate failure, with the narrower meanings below.

### `m3 rehearse`

```text
python -m disclosure_drift m3 rehearse
  --scenarios {all,<id>[,<id>...]}
  --evidence-root ABSOLUTE_EXTERNAL_PATH
  --evidence-out RELATIVE_PATH
  --receipt-out RELATIVE_PATH
  [--config PATH]
```

Runs A1–A12 against scripted transports only. Stdout is one redacted line per scenario plus a
summary. Exit `0` only when every requested scenario passes; the phase token requires `all`.

### `m3 rehearse-report`

```text
python -m disclosure_drift m3 rehearse-report
  --evidence-root ABSOLUTE_EXTERNAL_PATH --evidence RELATIVE_PATH
```

Read-only. Prints the scenario matrix, non-contamination result, and derived/tested route bounds.
Exit `0` only for a complete passing A1–A12 record.

### `m3 plan-requests`

```text
python -m disclosure_drift m3 plan-requests
  --coverage-start YYYY-MM-DD --coverage-end YYYY-MM-DD --as-of YYYY-MM-DD
  --calendar-year YEAR --calendar-evidence-manifest RELATIVE_PATH
  --catalog RELATIVE_PATH
  --evidence-root ABSOLUTE_EXTERNAL_PATH
  --plan-out RELATIVE_PATH --receipt-out RELATIVE_PATH
  [--config PATH]
```

Plans M3.2A only, constructs no transport, resolves no host, and makes zero requests. It has no
`--reconciliation-set`, `--live`, or M3.2B mode. Stdout is the per-route table, totals, and plan
hash; it contains no absolute path or SEC identity.

### `m3 show-budget`

```text
python -m disclosure_drift m3 show-budget
  --evidence-root ABSOLUTE_EXTERNAL_PATH --plan RELATIVE_PATH
```

Read-only. Renders the eight governed budget quantities and the exact derived ceiling. It does not
approve either integer.

### `m3 show-receipt`

```text
python -m disclosure_drift m3 show-receipt
  --evidence-root ABSOLUTE_EXTERNAL_PATH --receipt RELATIVE_PATH
```

Read-only. Validates schema, canonical form, field classes, prohibited content, reason registration,
accounting, recovery chain, and `receipt_id`. Exit `4` on any defect.

### `m3 recovery-state`

```text
python -m disclosure_drift m3 recovery-state
  --evidence-root ABSOLUTE_EXTERNAL_PATH
  --plan RELATIVE_PATH --receipt-chain-head RELATIVE_PATH
  --catalog RELATIVE_PATH --data-root RELATIVE_PATH
```

Read-only SQLite and filesystem inspection. Prints the interruption point, persisted/raw/projection
state, consumed physical attempts, required deterministic action, and one of `SAFE`, `UNSAFE`, or
`UNDETERMINED`. Exit `0` only for `SAFE`; the other determinations exit `4`. There is no `--run`
shortcut and no repair flag.

## 20. Completion tokens and commit boundary

M3.1A may emit exactly:

```text
M3_1A_OFFLINE_OPERATOR_REHEARSAL_PASSED
```

M3.1 as a whole may emit exactly:

```text
M3_1_GATE_F_READY_FOR_CONTROLLED_METADATA_ACQUISITION
```

Neither token is emitted by code existing, by tests passing, or by a contract being accepted. The
first requires every M3.1A acceptance item; the second additionally requires all M3.1B evidence,
the exact owner-approved M3.2A budget and ceiling, full validation, protected-path proof, and zero
network attempts.

The M3.1A token's predicate is exactly four conjuncts (Decision 029 §6):

```text
report.passed and report.complete and report.a_reachable_agrees and report.a_reachable_fully_tested
```

`m3 rehearse-report` must **recompute** the authoritative derived key set, exact tested-key equality,
the emptiness of `unmeasured_routes`, and numeric agreement rather than trusting a stored report, and
`_bounds_agree()` must not accept a subset. A diagnostic subset run may complete as a command but
must never emit the token.

The order in which the tokens, Gate F, and the tag may occur is frozen by Decision 029 §12.
**`m3.1-complete` before Gate F is prohibited**: contract §20 requires the owner-approved M3.2A
budget and ceiling before the overall token, and master plan §34 permits the tag only after
independent acceptance.

The commit boundary is the independently reviewed M3.1 implementation diff over exactly §6. Work
stops there. M3.2, any live SEC request, contract acceptance recording, checkpointing, pushing, and
tagging require their own explicit authorization.
