## 11. Snapshot-freeze semantics

- **What makes a snapshot frozen:** the `building -> frozen` transition, permitted only by migration
  `0009`'s `pilot_snapshot_transition_guard`, and gated by `pilot_snapshot_freeze_requires_valid_state`
  (declared entity and accession counts equal to the actual rows; exactly one anchor per accession)
  and by the row `CHECK` requiring `frozen_at_utc` and all nine content digests to be non-`NULL`.
- **Every Decision 019 §9 obligation must be validated at freeze**, and again at read time, and each
  must fail for its own stated reason rather than incidentally (rehearsal E2).
- **A frozen snapshot is immutable.** `pilot_snapshot_frozen_fields_immutable` holds all 22 content,
  policy, coverage, hash, and provenance fields, including across `frozen -> invalidated`;
  `pilot_snapshot_no_delete` refuses deletion of a `frozen` or `invalidated` row.
- **A wrong snapshot is superseded by a new one under explicit authorization, never edited** (master
  plan M3.3 §27).
- **Canonical snapshot identity** is `snapshot_id`, content-derived and excluding `census_run_id`
  (Decision 016 §1) — subject to **OR-1**.

`OWNER_RULING_REQUIRED: OR-5 — the authoritative state after an interruption at (a) snapshot freeze,
(b) selection persistence, (c) sealing, (d) manifest construction; and which owner instrument
authorizes invalidating or superseding a snapshot. Migration 0013 and master plan §28 make (b)-(d)
enumerable. For (a), a surviving 'building' row is possible and no accepted record says whether it
may be completed, must be invalidated, or is a stop condition. Partial authoritative state must fail

## 13. Persistence, reconstruction, and equality

**Persistence.** One `running` window per S5 run, ending at `running -> feasible` as the last
statement of one transaction. Reserves, contributions, members, quota results, and dispositions are
written inside that same window (Decision 020 §7). Exactly one `proposed` manifest row, written
atomically with its document (Decision 021 §11.3).

**Equality that must be proven.** Three states must agree, and nothing stored is trusted that was
not re-derived (Decision 021 §12):

1. **Selected result → persisted state.** Every persisted component is validated against the
   re-derived pure result; a corrupted, incomplete, contradictory, or policy-mismatched persisted run
   raises `GateFailureError`.
2. **Persisted state → independently reconstructed state.** `reconstruct_persisted_joint_selection`
   re-derives the result from the same frozen snapshot under the run's own recorded seed, policy
   versions, and node limit, and compares **field by field** through the single centralized
   `JointSelectionRunIdentity` comparison — order-independent, with **neither public entry point more
   permissive than the other**.
3. **Persisted rows → every governed identity.** Each of the eight component digests,
   `selection_result_sha256`, `root_manifest_sha256`, and `manifest_id` is recomputed **from
   persisted rows, never from memory**, and compared; the document is re-rendered and re-serialized
   byte-identically; verification is item by item over all 81 crosswalk items.

Any difference at any layer is a `GateFailureError`. **Reconstruction repairs nothing**, and stored
identity corruption is a stop-and-report condition.

## 14. Write-free replay

Replay **reads, reconstructs, compares, and returns** (Decision 021 §§11.3, 12). It issues no
`INSERT`, `UPDATE`, `DELETE`, `INSERT OR REPLACE`, `REPLACE INTO`, or `INSERT OR IGNORE` against
`pilot_manifest_versions` or `pilot_selection_runs`; migration `0013` triggers 5 and 6 refuse one if
it were ever issued. An identical re-seal is idempotent; a differing seal is refused. Rehearsal E8
additionally requires persisted state **byte-identical before and after each replay**, with the
receipt the only thing that differs between two replays.

`OWNER_RULING_REQUIRED: OR-3 — the exact write-free proof standard. Decision 066 R1 requires every
pre-existing durable evidence artifact, including the main SQLite catalog file, to remain
byte-identical, and states its generality as "general for reconcile-requests"; it does not extend
itself to M3.3. Decision 021 §§11.3, 12 define write-free as issuing no mutating statement. E8
demands byte-identical persisted state. The owner must fix (a) whether the M3.3 proof is durable-byte
equality or logical-row equality, (b) which connection mode each M3.3 read path must use —
strictly_read_only_connection opens SQLITE_OPEN_READONLY and cannot checkpoint, while
read_only_connection is read-only by convention on a read-write OS handle that can checkpoint on
close — and (c) whether the writer lease applies to a read-only M3.3 path. Transient -wal/-shm
sidecar handling remains separately governed and is never a licence to change the main database
bytes.`

`OWNER_RULING_REQUIRED: OR-8 — whether strict read-only hardening of the remaining
convention-only read paths must land before M3.3-I/R. The complete inventory is in
Docs/m3/m3_3_governance_foundation_inventory.md §K, CF4.`

## 16. Manifest component model, `manifest_id`, and `root_manifest_sha256`

**Eight components**, each at its frozen preimage: `selected_entities_sha256` (§7.1),
`selected_accessions_sha256` (§7.2), `quota_report_sha256` (§7.3, four sub-digests),
`reserves_sha256` (§7.4, four sub-digests), `source_observation_set_sha256` (§8.1, including the

`quota_definitions_sha256` (§8.3), and `selector_policy_sha256` (§8.4, eleven fields including the
six explicit arguments and the fixed `leakage_attestation` literal).

**`root_manifest_sha256`** is the single-row `pilot_root_manifest` digest over exactly the twelve

approval field, `supersedes_manifest_id`, `relative_manifest_path`, `generated_at_utc`, `detail`,
`manifest_id`, and every event ID.

**`manifest_id`** is the single-row `pilot_manifest_identity` digest over exactly
`{root_manifest_sha256, ordinal_version, supersedes_manifest_id}` with `NULL_SENTINEL` for an absent
predecessor (§9.1). At this phase `supersedes_manifest_id` is always the canonical `NULL` (§11.1).
Six identity fields are immutable from insertion (§9.2), enforced in code and by migration `0013`
trigger 4.

**Component order, serialization, and derivation are not re-specified here.** They are frozen by
Decision 021 and implemented in `release/pilot_manifest.py`; **no second hashing implementation, no
parallel normalization, and no alternative canonical-JSON encoder may be created** (§5). The graph is
acyclic (§10), and commitment closure holds: the root commits every substantive value, `manifest_id`
commits the root plus the two version-ordering fields, and together they commit the whole document
(§10.1, §13.3).

`OWNER_RULING_REQUIRED: OR-6 — the exact values of the six Decision 021 §8.4 explicit arguments for

## 17. Atomicity

- **One explicit transaction per manifest write** — row and document commit together or not at all.
  A fault leaves **no** new row and **no** new file; a **pre-existing** artifact at the
  content-derived path is outside the transaction's ownership and is not deleted (**D023-O3**).
- **Sealing is a separate, prior transaction** (§15).
- **A failed selection leaves the run in its recorded failed state — it is not deleted**, and no
  automatic retry occurs (Decision 018 §18).
- **A failed freeze leaves no partial snapshot.**
- **Partial authoritative state fails closed** at every boundary — see **OR-5**.

## 18. Identity effects, and the operational envelope

This phase produces `snapshot_id`, `selection_run_id`, `selection_input_sha256`,
`selection_result_sha256`, the eight component digests, `root_manifest_sha256`, and `manifest_id`.

**No operational value enters any of them.** Decision 016 §8's exclusions apply to every digest
without exception — absolute local paths, SEC identity, secrets, any outcome value, any filing text,
every free-text `detail`, every operational event ID, and **every timestamp column**. Approval and
publication state (`manifest_state`, `approval_reference`, `approved_root_sha256`, `approved_at_utc`,
`rejected_at_utc`, `superseded_at_utc`) are excluded from every digest **and** from the document's
substantive body (Decision 021 §13.4). `acceptance_audit_date` is the one deliberate inclusion: a
calendar date and a frozen candidate classification input, not a timestamp (Decision 019 §10).

**The receipt records identities as references and is never an input to any digest** (master plan
M3.3 §22). The direction is one-way.

**No governed identity depends on physical SQLite bytes or on SQLite-version-specific serialization.**
Every one is a logical `hash_table` digest over normalized, sorted row content.

## 32. Failure, rollback, and recovery

A failed manifest write leaves **no** row and **no** new file; a pre-existing artifact at the
content-derived path is not deleted (**D023-O3**). A failed selection leaves the run in its recorded
failed state — it is **not** deleted, and no automatic retry occurs. A frozen snapshot is immutable;
a wrong one is superseded under explicit authorization, never edited. **Nothing acquired in M3.2 is
touched.** Recovery uses
[`Docs/m3/templates/interrupted_run_recovery.md`](../../Docs/m3/templates/interrupted_run_recovery.md)
and the enumerable safe states migration `0013`'s guards establish (master plan M3.3 §28); identical
restatement is idempotent, and anything else is a stop condition. See **OR-5** for the snapshot-freeze
boundary.

## 33. Commit, tag, and completion-report policy

- **One implementation commit per part** by default — M3.3A's builder and harness, then M3.3B's

  independent review sits between them and a review needs a committed state; it is taken only if the

## 35. Terminal token, and the M3.4 separation
